# /migrator-run-task — безпечний запуск переносу

Дисципліна навколо `python -m migrator run <корінь>:<завдання>` - щоб не
зіткнутись із зависанням/конфліктом сесій 1С (див. `baf-skills`'
`1c-thick-client-hang-diagnosis`) і щоб результат був видимий, а не лише
"процес завершився".

## Крок 1. Перевірити, що немає активної сесії 1cv8.exe

```powershell
tasklist /FI "IMAGENAME eq 1cv8.exe" /FO CSV /NH
```

Якщо є - це або (а) недозавершена попередня сесія Migrator (перевірте, чи
не завис попередній запуск), або (б) РУЧНА сесія користувача (НЕ вбивайте
без підтвердження - спитайте користувача). Паралельні сесії проти
файлової бази-приймача спричиняють конфлікти блокувань.

## Крок 2. Валідувати схему ПЕРЕД запуском

```powershell
cd <шлях_до_Migrator>
python -c "from migrator.schema import load_schema; from migrator.config import resolve_schema_path; load_schema(resolve_schema_path('<корінь>:<завдання>'))"
```

Ловить помилки YAML/структури схеми ДО того, як BridgeTool витратить ~20с
на холодний старт.

## Крок 3. Перший запуск завдання - ЗАВЖДИ з `--limit`

```powershell
python -m migrator run <корінь>:<завдання> --limit 5
```

Підтвердьте: очікувана кількість записів, немає ПОМИЛОК у виводі
(`ОШИБКА <uuid>: ...` рядки означають, що ЩОСЬ пішло не так для КОНКРЕТНОГО
запису - не ігноруйте їх мовчки, навіть якщо підсумковий "Успешно" > 0).

## Крок 4. Повний запуск (без обмеження)

```powershell
python -m migrator run <корінь>:<завдання>
```

**Тайм-аут:** повний перенос з каскадами може тривати кілька хвилин - КОЖЕН
COM-запит (головний + КОЖЕН каскад + КОЖНА табличная частина) має
ФІКСОВАНУ накладну вартість ~20-30с (з'єднання/компіляція запиту на
сервері), НЕЗАЛЕЖНО від кількості рядків - тому час масштабується з
КІЛЬКІСТЮ каскадів, не з обсягом даних. Плануйте тайм-аут з розрахунку
~30-40с на кожен очікуваний COM-запит (головний плюс один на кожен
`related_catalogs`, плюс один на кожну `tabular_parts`).

## Крок 5. Прочитати результат

Вивід містить, по кожному довіднику (головному й каскадах): "Итого: N,
Успешно: M". **M < N - НЕ помилка запуску скрипта, а часткова невдача
запису** - деталі в тексті після підсумку (`ОШИБКА <uuid>: <причина>`) або
у `logs/engine/<сесія>/write_progress.log`
(для головного) чи `cascade_<довідник>.log` (для кожного каскаду - Phase 7
Migrator, до якого без цього прогрес не писався взагалі й помилки були
невидимі).

Часті причини часткової невдачі (не завжди помилка переносу - див.
`/migrator-verify-transfer` для розрізнення):
- Бізнес-правило приймача відхиляє запис (напр. обов'язкове поле, похідне
  від чогось порожнього в джерелі) - прогалина в ДАНИХ джерела, не в коді.
- `УникальныйИдентификатор("")` / "Invalid parameter value" - ЯКЩО бачите
  це на конкретних записах - перевірте версію `com_query.ps1` (одно-рядкові
  результати запиту мають власний баг у старих версіях Migrator <0.8.0 -
  оновіть Migrator, якщо бачите цю помилку).

## Крок 6. Після завершення

Запустіть `/migrator-verify-transfer` - рігорозне порівняння джерело/
приймач, а не лише довіра до підсумкового "Успешно: N".
